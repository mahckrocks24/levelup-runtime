# Runtime v2.34.3 — honest-framing

**Base:** v2.34.2-repoint-complete (all repoint work carried forward).

**What:** the daily/weekly/monthly Sarah synthesis prompts (`lu-sarah-synthesis-routes.js`)
no longer let Sarah imply she autonomously executes work.

**Why:** 2026-06-30 "say vs do" forensic found Sarah's autonomous briefs/onboarding
imply execution ("sit back, I'll handle it", a bare "TODAY:" action list) while NOTHING
runs — proposals sit `pending_approval`, no tasks/sequence-enrollments are created. The
live daily brief is generated by this runtime endpoint (`/internal/sarah/synthesize-daily`,
Path A in Laravel's `SarahDailyOrchestrator`), so the framing fix has to live here. The
Laravel-side onboarding text + aiRun fallback prompt were fixed in the same session.

**Change (daily prompt):**
- Action section relabeled `TODAY:` → must read exactly **`RECOMMENDED FOR TODAY — approve to run`**.
- New rule: **TRUTH IN FRAMING** — every action is a PROPOSAL the owner must approve before
  it runs; never state/imply anything is running/queued/scheduled/started/done; never say
  "sit back", "I'll handle it", "I've started", etc. Phrase as recommendations.

**Not changed:** weekly/monthly prompts already emit `proposed_actions` and pivots (proposal
framing); left as-is to keep the diff minimal. Revisit if they show the same overclaim.

**Verification:** `node --check` passes (local v24; re-checked on droplet v20 == Railway).
NOT runtime-tested e2e (cannot deploy Railway from build host).

**Deploy (Shukran → Railway):** push v2.34.3. No new env vars. After deploy, a generated
morning brief should label the section "RECOMMENDED FOR TODAY — approve to run" and contain
no "I'll handle it / sit back" phrasing.
